# C 聚焦舞台 · 原生实现与验证

日期：2026-09-05。设计确认见 [direction-approved.md](direction-approved.md)。

C 的结构已落实到现有 Android Compose 应用：左侧导航、首页卡带舞台、游戏库列表与预览、以开始按钮为主的详情页、两级设置。沿用项目色板、图标和五款示例游戏。

## 已实现

- 所有页面共用焦点边框、按钮与按键提示，统一处理方向键和左摇杆方向事件。
- 首页前后切换游戏，全部、收藏、最近游玩入口；游戏库按名称升降序排列。
- 详情返回保留选中游戏和列表位置；取消收藏前将焦点移到筛选按钮，避免删除焦点节点后跳到侧栏。
- 排序和减少动效通过 DataStore 保存。进程恢复时先读取保存的排序，再初始化页面焦点；导航图持续挂载以恢复页面栈。
- 按钮显式允许在 Android 触控模式下获得焦点。短屏收紧次要信息，封面保持比例并裁剪网格绘制边界，内容避开系统安全区。
- 中英文界面使用 Android 字符串资源；收藏状态和前后切换按钮提供语义说明。

当前仍是应用壳层：ROM 扫描、外部模拟器配置和启动、视频预览尚未接入。相关操作会显示明确提示。示例库的收藏仅在本次运行中有效，尚未接入 Room 持久化。

## 构建与自动检查

配置 JDK 17 和 Android SDK，确保 `JAVA_HOME`、`ANDROID_HOME` 指向对应安装目录后，在仓库根目录执行：

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --offline --console=plain
```

结果：构建成功；9 项单元测试通过；Lint 0 错误、5 条依赖版本提示；`git diff --check` 通过。

新增 5 项筛选排序测试，覆盖隐藏游戏、最后一个收藏被移除、最近游玩顺序、设备语言对排序的影响，以及 5,000 条数据的完整性。这些是数据逻辑测试，不代表 5,000 条游戏的滚动性能验收。

APK：`app/build/outputs/apk/debug/app-debug.apk`。

## Android 运行验证

模拟器为 Android 35 ARM64，160 dpi。检查了 960×600、640×480、800×450、640×360 四种横屏逻辑画布。

| 场景 | 已观察结果 |
| --- | --- |
| 首页 → 右方向键 → A → B | 开始按钮打开启动提示；关闭后焦点回到开始按钮 |
| X 详情 → Y 收藏 → B | 收藏状态更新；返回原页面和操作位置 |
| 列表连续按下方向键到末尾 → X → B | 边界不越界；回到同一游戏行 |
| 收藏列表逐项取消，直到为空 | 焦点留在收藏筛选；可直接切回全部游戏 |
| 修改排序、减少动效后冷启动 | 两个设置保持修改后的值 |
| 列表选中游戏 → 后台 → 回收进程 → 返回 | 已确认进程号变化；页面、选中游戏和行焦点恢复 |
| 矮屏首页、详情、游戏库、设置 | 主按钮可达，文字可读，焦点边框可见；设置分类可滚动 |

## 已连接手机

一加 PLK110，Android 16，物理分辨率 1272×2772，密度 560 dpi。最新 APK 已保留应用数据安装，并运行横屏中文界面。

已通过方向键、A/B/X/Y 注入事件检查：首页初始焦点、启动提示与返回、收藏开关、详情返回、列表位置恢复和设置页面。收藏测试后切回原状态。另已验证触控打开详情后，开始按钮仍有焦点，B 键能返回并恢复焦点。未观察到 AndroidRuntime 崩溃日志。

# 游戏库排列探索

本轮只重排 RiftDeck 的游戏库页面，保留 Android 横屏掌机、十字方向键优先的使用方式。当前用户先反馈预览边框跳变，随后反馈画面过小；前两项已经在应用中修复。因此新版排列不能再次牺牲预览面积，也不能在切换游戏时让周围的标题、按钮和筛选栏跟着移动。此次先交付三份可交互 HTML 初稿，得到方向选择后再修改 Compose 实现。

统一画布为 960×640，与本轮真机截图一致。画布在浏览器中等比缩放，不拉伸；页面之外可以有简短的方案标识，画布里面只放产品内容。基本结构包括现有窄图标导航、RiftDeck 字标、游戏库标题、全部/收藏/最近筛选、排序与搜索入口、游戏选择区域、选中游戏名称、开始游戏操作及底部控制提示。导航图标可以使用已有简单线性图形，不能用 emoji。正文至少 18px，主要游戏标题 24px 左右，小标签至少 14px，背景纯黑，主文字近白，选中边框亮黄，次强调青色，面板为深灰青。尽量减少边框套边框，避免将每条信息都包成独立卡片。

产品风格由现有品牌资产决定：使用 assets.json 中的真实独立字标，黄色与青色对向切角，暗色、清晰、克制。三个方向共同使用项目已有的五款示例游戏，不编造真实游戏资料；其中几何封面是已有示例占位素材，必须在页面画布外注明“示例封面，仅比较排列”。没有重新制作游戏封面或添加外部品牌。原型中的预览区域可使用选中示例封面，但须明确文字“视频预览区域”，不可假装存在真实游戏视频。字标与图片全部作为 data URI 内嵌，单文件可离线打开，无外部依赖。

三个版本应体现真正不同的选择方式，而非换颜色。A 以按名称检索的高效纵向列表为主，压缩左侧条目宽度，将更大面积留给右侧固定预览。B 用封面网格作为主要视觉锚点，方向键在行列间移动，选中项目与底部动作区联动，避免另放很小的重复预览。C 以大画面为主，底部横向封面带承担选游戏的操作，左右切换、上下在筛选和游戏带之间移动。三版都有明显焦点，支持键盘方向键和点击切换，Enter 显示详情预览而不真正启动模拟器，Escape 关闭；不要产生联网行为。

比较标准：一眼看清当前选中游戏、可用空间利用充分、横屏内容不缩在竖版窄框中、名称较长时不遮挡按钮、相邻游戏可判断移动方向、焦点样式统一。正式实现仍需兼容四比三和十六比九，但这轮统一尺寸横向比较，避免尺寸差异误导选择。所有生成内容只属于设计草稿，不改变已安装应用，也不修改当前业务源码。
